# 在线评估质量端到端验证报告

> 状态：验证完成 | 同步：2026-08-11 | 数据源：真实 trace（3738 条）+ 生产向量库（3761 blocks / 5 docs）

## 1. 验证方法

```
真实 trace 抽样（按通道分层 16 条）→ 生产 store 检索复现（hybrid keyword+vector，同线上路径）
→ 本地 BGE reranker 客观打分（bge-reranker-v2-m3，sigmoid 0-1）
→ DeepSeek LLM judge 打分（judge_self.py，0-1 + 理由）→ 人工案例裁决
```

- 复现路径：`HierarchicalNovelStore.search(channel, doc_id, filters)`（与线上一致，含 fallback）
- 双信号交叉：judge（可解释）vs BGE（客观）→ 一致性 + 分歧案例人工裁决
- 复现脚本：`scripts/dev/verify_eval_quality.py`（诊断用途，非 CI）
- 原始数据：`data/traces/eval_quality_report.json`

| 指标 | 值 | 说明 |
|------|-----|------|

| 复现零命中率 | 25%（4/16） | 与 trace 记录一致（25%）—— 复现忠实 |
| 零命中分布 | **qa 通道 4 条全零命中** | qa 通道薄弱（QA 块少/未生成） |

| judge × BGE 方向一致性 | 50%（8 对） | 分歧集中于两类盲区（见下） |

## 3. 分歧案例人工裁决（核心发现）

| Query | judge | BGE | 人工裁决 | 说明 |
|-------|-------|-----|---------|------|
| 那大战结束之后呢？ | 0.8 | **0.054** | **judge 对** | hit 明确含"帝国的战斗结束后…忙碌"，BGE 对代词指代类 query（"那/之后"）只看字面，严重漏判 |
| 朱菜和利姆露在商量什么？ | 0.2 | 0.655 | **judge 对** | hits 有朱菜互动但无"商量"内容，BGE 词面相关偏乐观 |
| 八奈见杏菜 后来你不是在公园看到草芥了吗 | **1.0** | 0.176 | **BGE 对** | hits 是草介告别场景但**无"公园"情节**，judge 给满分过度乐观 |
| 史莱姆是怎么样的生物 | 0.2 | 0.603 | 持平 | hits 仅顺带提"史莱姆是可怕魔物"，无物种特征；BGE 偏乐观、judge 偏严 |

**盲区结论**：
- **BGE 盲区**：代词/指代类 query（"那…之后"、"他"）字面重叠极低 → 分数失真偏低（1/4 案例严重误判）
- **judge 盲区**：精确情节匹配要求高时偶发"满分过度"（未命中公园场景却给 1.0）；整体理由具体、可解释性强
- 分歧 4 例中：judge 对 2、BGE 对 1、持平 1 → **judge 略优，但两者都不可独信**

## 4. 对"在线评估系统"输出质量的评价

**做得对的部分**：
- judge 理由与 0-1 分档标准（人物/情节/台词证据）吻合，可解释、可审计
- 复现零命中率与 trace 记录一致 → trace 数据可信、评估链路忠实
- 低分项（"阿溪 对话"、"八奈见杏菜 你平时喜欢吃什么？"）确为弱相关 → **低分回收有效**

**发现的问题（影响评估准确性）**：
1. **qa 通道整体零命中**（4/4）—— 评估页该通道统计失真，根因是 QA 块缺失，不是评估系统本身
2. **judge 满分倾向**：1/8 例对未命中核心情节仍给 1.0 —— 建议 judge 提示词增加"必须命中 query 全部关键实体/情节才算 1.0"
3. **单信号不稳健**：judge×BGE 一致性仅 50%，建议评估页同时展示两个信号（现状只展示 judge）

## 5. 建议（按优先级）

1. **补充 QA 通道**：`generate_qa` 或 QA 生成任务，解决 qa 检索零命中
2. **judge 提示词收紧满分标准**：关键实体未全部命中时上限 0.8
3. **评估页双信号展示**：judge（可解释）+ BGE（客观）并列，分歧项标黄
4. （可选）检索质量改进：dialogue 通道候选稀少（top_k=5 仅返回 1 条），检查 dialogue 块量与过滤

## 6. 验证边界

- 抽样 16 条（控制 API/推理成本），统计置信度有限；结论方向可靠（双信号交叉 + 人工裁决）
- BGE 分数为对"未重排候选"的绝对打分，与线上"rerank 后"相关性有差异（线上有 BGE rerank 步骤，分数会更高）
- 本次验证未修改任何生产代码
