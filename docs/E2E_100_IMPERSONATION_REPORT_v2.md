## 三、强制注入的效果与代价

### 效果（P3 修复验证）
1. **工具必然被调用**：每轮扮演强制执行 relations + character_events 查询
2. **指标必然产生**：tool_value 141+163 次 valuable，判断回收数据充足
3. **世界知识进上下文**：亚瑟答"莉娜是什么位置"引用了关系数据；老首领答"你恨马库斯吗"有反派视角

### 代价（新问题）
1. **带引用率 99% → 84.4%**：强制注入的关系/事件摘要是"行级摘要+证据指针"，不是原文块 → 回答靠摘要时不产生 citation
2. **耗时 6s → 14s**：每轮 2 次 SQL 查询 + 摘要格式化
3. **回答可能"半凭摘要"**：摘要信息不全时角色会补演绎（见 P2）

## 四、发现的问题

### P1（严重，检索盲区）：莉娜「你救过老赵吗」回答错误
- 原文：支线一明确写了莉娜救治猎户老赵（"雷恩，把老赵送去客房"）
- 实际回答：**"哨站里没有叫老赵的人"** —— 角色否认了原文事实
- 根因：强制注入的 relations/character_events 不包含"老赵"这个次要角色；向量检索也因"老赵"出现次数少（3 次）未被召回 → 角色凭知识边界诚实说"不认识"
- **这暴露了知识边界设计的固有张力：检索不到 = 角色"不知道"= 答错原文事实**。检索覆盖率是知识边界正确性的前提

### P2（中等）：摘要驱动回答缺引用
- 艾琳「你还会留在哨站吗」→"我只是个商队首领"（与原文"决定留下"矛盾）
- 莉娜 5 个 0 引用回答：内容对（有原文细节）但无引用
- 根因：world_knowledge 返回行级摘要，LLM 用摘要作答不带引用；摘要语义偏差（"商队首领"是艾琳过去身份）导致轻微 OOC

### P3（低）：角色间引用率不均
- 亚瑟/维克托/雷恩/老首领/小卡 100%，艾琳 42%、莉娜 58%
- 艾琳/莉娜的问题偏"内心/关系"类（"你会留下吗""你怎么看"），检索难命中原文，更依赖摘要

### P4（观察）：耗时翻倍
- 14s/次（工具查询 + 检索 + 2 次 LLM），96 次约 23 分钟

## 五、结论

1. **强制注入修复了工具利用率（0→100%），world_knowledge 成为有效的事实通道**（valuable 压倒性）
2. **代价是引用率下降**（99→84%）——回答部分依赖摘要而非原文
3. **最严重的新问题：检索盲区导致角色"诚实地答错"**（老赵事件）——这比编造更隐蔽，因为角色表现得符合"知识边界"人设，但事实是错的
4. **判断回收机制完整运作**：retrieval_relevance 93.4%、tool_value 量化、answer_coverage 38/1——每个维度都有数据可改进

## 六、建议

1. **P1 修复**：检索召回增强——次要角色事件（老赵/柱子/阿贵）需要更高召回；或 world_knowledge 强制注入增加"角色相关次要人物"查询维度
2. **P2 修复**：摘要回答时附 evidence block_id → 触发 novel_search 取原文 → 恢复引用（摘要与原文双通道）
3. **P3 观察**：内心/关系类问题可允许无引用（本就是摘要可答），但需 answer_coverage 兜底标记
4. **P4 优化**：工具查询并行化（relations/character_events 一次调用合并）
