## 三、回答质量（人工抽查）

### 时间类（最考验检索的锚点能力）—— 优秀
- 「十年前你父亲战死的时候，你在哪里？」→ 准确复述序章（十三岁、地下室火炉边、带血徽章、鹰与剑纹章）—— 逐细节命中原文
- 「你是什么时候当上指挥官的？」→ "五年前的那个冬天" + 借粮细节 —— 正确（对应支线四十一五年前回忆）
- 「后来黑旗军怎么样了？」→ 正确串联（翻过灰脊山→军械现塔利斯车→老首领是仇人）

### 关系类 —— 优秀（角色有独立视角）

- 亚瑟「你恨维克托叔叔吗？」→ "恨？不。这个问题我想过很多年" —— 情感复杂度符合人设

### 知识边界（角色只知道自己的事）—— 通过

## 四、发现的问题

### P1（严重）：temporal 类提问依赖"角色卡背景"，而非时间线检索
- 时间类回答准确，但**证据来自角色卡 background + 检索命中的叙事块**，不是时间线维度的结构化召回
- 例：「你是什么时候当上指挥官的？」—— 正确回答来自支线四十一（五年前回忆）恰好被向量检索命中，**不是**通过 chronicle/by_era 时间锚点定位
- 风险：如果提问"那件事发生在他当指挥官之前还是之后？"这类**需要时间排序**的问题，当前链路只能碰运气

### P2（中等）：事件类 1 次 0 引用（卡洛琳·怀特问"黑旗军来袭那天你在做什么"）
- 回答内容正确（厨房煮汤→听见马蹄声→往外跑），但无引用
- 原因：该情节在原文是叙述带过（"小卡把厨房里的所有锅都端了出来"），角色卡无此细节，检索未命中 → LLM 凭人设合理演绎，但**无引用 = 无事实依据**
- 这正是"LLM 后处理判断回收"要暴露的问题：answer_coverage 若为 0，应标记"无依据回答"

### P3（低）：检索相关率 97.6% 但 tools 无 world_knowledge 调用
- 96 次扮演中 world_knowledge 工具**未被调用**（tool_value 只有之前手动测试的 2 次）
- 原因：扮演 prompt 的 _TOOL_AWARE_PROMPT 引导 LLM 用工具查"超出原著知识范围"的信息，但角色扮演下 LLM 倾向用角色知识直接回答（人设优先）
- 影响：world_knowledge 在扮演场景实际利用率低；**判断回收指标主要来自检索相关率，工具价值率几乎无数据**

### P4（观察）：引用数 81/96 都是 5 条（top_k 上限）
- 5 条引用是默认 top_k，未随问题复杂度自适应
- 简单问题（"你最喜欢哪道菜"）也 5 条引用，上下文有冗余

## 五、结论

1. **整体质量高**：100% 成功、99% 引用、时间/关系/日常回答均准确，角色有独立视角和知识边界
2. **核心验证成立**：5 万字数据量下，向量检索 + 角色卡 + 剧情分析足以支撑 96 次不重复的多方向扮演
3. **待改进**：
   - P1 时间线结构化召回未接入（world_knowledge 工具没被扮演 LLM 主动调用——**工具可见性/引导不足**）
   - P2 无依据回答无法拦截（answer_coverage=0 时应降级为"不知道"）
   - P3 扮演场景工具利用率低（需在扮演 prompt 中强化"查证"引导，或让检索阶段自动预取时间线）
4. **判断回收机制有效**：retrieval_relevance 97.6% 证明"LLM 后处理判断"能真实度量检索质量——这正是本次评估的机制验证目标

## 六、建议下一步

1. 扮演 prompt 增加"时间性/关系性问题先查 world_knowledge 再回答"的引导（提升工具利用率）
2. answer_coverage=0 时强制"不知道"降级（拦 P2 类无依据回答）
3. 检索前自动注入时间线锚点（chronicle seq 定位），让"后来/之前"类问题结构化命中
